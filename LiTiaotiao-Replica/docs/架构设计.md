# 架构设计

## 1. 总体架构

```
┌─────────────────────────────┐         ┌──────────────────────────────────────┐
│  浏览器 (SPA)               │  HTTP   │  后端 (Python 标准库)                │
│  static/index.html          │ ──────▶ │  litiaotiao/server.py                │
│  static/js/{api,app}.js     │ ◀────── │    ├─ 路由分发 (ThreadingHTTPServer)   │
│  static/css/styles.css      │  JSON   │    ├─ api.py  (路由处理 + 统一错误)    │
└─────────────────────────────┘         │    ├─ engine.py (规则引擎 ★)          │
                                        │    ├─ rules_io.py (AllRules 格式)      │
                                        │    ├─ hashutil.py (Java hashCode)     │
                                        │    ├─ package_index.py (hash↔包名)    │
                                        │    ├─ db.py (SQLite 封装)             │
                                        │    └─ seed.py (数据初始化)            │
                                        └───────────────┬──────────────────────┘
                                                        │
                                              ┌─────────▼─────────┐
                                              │  SQLite             │
                                              │  litiaotiao.db     │
                                              └─────────────────────┘
```

- **零外部依赖**：后端仅用 Python 标准库，前端无需构建，开箱即跑。
- **职责清晰**：HTTP 层（server）只负责传输与静态资源；业务逻辑在 `api`；核心算法在 `engine`；持久化在 `db`。
- **统一错误处理**：`api.ApiError(status, msg)` 由 server 统一转成 JSON；其余异常兜底为 500。
- **统一日志**：`logging_setup` 同时输出到控制台与 `data/litiaotiao.log`。

## 2. 数据模型（SQLite）

| 表 | 关键字段 | 用途 |
| --- | --- | --- |
| `apps` | `hash`(PK), `package`, `display_name`, `enabled`, `whitelisted`, `source` | 应用主记录（hash = Java hashCode(包名)） |
| `rules` | `id`, `app_hash`, `rule_type`(popup/keyword/keyword_append), `match_id`, `action`, `times`, `sort_order` | 规则明细 |
| `app_params` | `app_hash`, `key`, `value` | 应用级参数（click_way_popup 等） |
| `settings` | `key`, `value` | 全局设置 |
| `skip_logs` | `app_hash`, `rule_type`, `trigger_text`, `action_kind`, `action_target`, `created_at` | 跳过日志（统计用） |

> 设计取舍：将官方「一个 JSON 字符串」拆成关系型存储，便于按应用/规则增删改查与检索；导出时再由 `rules_io.build_export_array` 还原成官方格式，**无损往返**。

## 3. 规则引擎（核心）

`engine.py` 将「屏幕」抽象为节点树 `UiNode`（text/resource_id/bounds/class/clickable/visible/checked/children）：

1. **匹配** `match_condition`：根据前缀 `+ - =` 选择 startsWith/endsWith/equals，否则模糊包含；`&` 拆分为 AND 子条件；对节点的 `text` 或 `resource_id` 求值。
2. **定位动作** `resolve_action`：
   - `GLOBAL_ACTION_BACK` → back；
   - 坐标格式 → bounds；
   - 否则按 `action` 文本/id 定位可点击控件（找不到且 `force` 时回退点击命中控件）。
3. **评估** `evaluate_screen`：先处理开屏关键词，再处理弹窗规则；支持 `times` 多次点击、`times=0` 仅检测、`search_times_popup` 多次扫描（同屏规则去重）、`unite_popup_rules` 连续任务建模。

## 4. 包名反查

原规则文件只有 `hash` 没有包名。本项目用 `scripts/build_package_index.py` 遍历社区规则库的目录结构（目录名即包名），用 `Java String.hashCode` 复刻算法算出每个包名的 hash，生成 `data/package_index.json`，从而在界面上展示真实**包名与应用名**。

## 5. 配置与敏感信息

所有可环境化的配置集中在 `litiaotiao/config.py`，读取环境变量（`LTT_PORT`、`LTT_DB_PATH`、`LTT_CUSTOM_RULES_DIR` 等），提供安全默认值，**不硬编码任何密钥**。`.env.example` 给出模板。

## 6. 运行流程

```
python run.py
  ├─ seed_from_file()      # 首次/每次启动导入社区规则（幂等，按 hash 覆盖）
  └─ server.run()
       ├─ db.init_db()     # 建表
       ├─ ensure_default_settings()
       └─ ThreadingHTTPServer.serve_forever()
```
