# 已知问题 / 局限

1. **运行载体差异（非缺陷）**
   原版李跳跳是 Android `AccessibilityService`，在真机上实时监听窗口事件并遍历无障碍节点树。
   本复刻在**无 Android SDK / 无设备**环境下，以**功能等价**的 Web 工作台替代：规则匹配与点击决策逻辑与原版一致，
   但「实时监听窗口」由「模拟器中的节点树快照」替代。逻辑可验证，载体不同。

2. **`delay` / `delay_popup` 未实际延时**
   参数已建模、可存储与导出，但引擎在单次屏幕评估中未实现毫秒级延时点击（真机用于等待动画）。
   不影响命中与点击目标的判定，仅缺少时序等待。

3. **`unite_popup_rules` 连续任务为单帧建模**
   原版的「持续任务」（如倒计时后按钮可点、自动安装）依赖多次窗口事件驱动。本引擎在**一次屏幕快照**内
   能识别 `times=0` 的检测态规则与对应的点击规则，但无法跨越多次快照推进「等待→出现→点击」的完整时序。
   模拟器可在不同快照上分别运行以演示各阶段。

4. **`|` 前缀按字面文本处理**
   官方文档仅定义 `+ - = &` 四种匹配前缀。数据中出现的 `| 跳过` 在本实现中按**模糊包含的 literal 文本**处理
   （与社区规则文件中该写法作为跳过按钮文案的实际情况一致）。如需将其定义为某种「或」语义，可在 `engine.match_condition` 扩展。

5. **坐标点击在真实设备上的约束**
   基于 `bounds` 的规则（`x1,y1,x2,y2`）依赖控件坐标，而坐标随设备/分辨率变化。社区规则库已建议避免使用纯 bounds 规则；
   本工作台如实保留该能力，但与原版一样存在设备相关性。

6. **服务端口冲突**
   默认端口 `8000` 在本机若被占用，请用 `LTT_PORT=8011 python run.py` 指定其他端口。

7. **种子数据来源**
   初始规则来自社区 `AllRules.json`（Snoopy1866/LiTiaotiao-Custom-Rules），其覆盖范围与时效以社区维护为准；
   可通过「规则导入」随时用最新官方/社区规则覆盖更新。部分应用官方已停止维护（原项目 2023-08 停更）。

8. **未编译 Android 原版 APK**
   因缺少 Android SDK / Gradle 工具链，本环境**未**尝试反编译或重新编译加固后的 APK（腾讯乐固导致 DEX 加密，静态反编译不可行）。
   所有功能均基于**已成功提取的资源、字符串、布局清单、无障碍配置与规则 JSON** 还原，未使用任何伪代码或占位实现。
